# Packaging a Windows update

1. Set `appVersion` in `update.go` and add `docs/releases/v<version>.md`. Use the three-language format (简体中文, 繁體中文, English) of the previous entry. The Go binary embeds the notes. Its title, PE version and installer version all use the same source constant.
2. Run `.\Build_Setup.ps1` from PowerShell on Windows with Go and Inno Setup 6.5+ (6.x). To specify a compiler or output location use `-Compiler`, `-Go` or `-OutputDir`. This builds locally; it does not create tags, push commits or publish releases. The installer does not bundle BASS DLLs.
3. Test the resulting installer on a clean install and over an older install. Both installed and portable configurations live beside the EXE in `runtime/config`. Upgrade in place to keep them. A new directory is a new installation; it does not search the computer for other copies.
4. When a release is authorized, prepare a **draft** GitHub release in Meidios/Auralux-Player with tag `v<version>` and copy the matching notes verbatim into its body. Attach `AuraluxPlayer-<version>-windows-x64-setup.exe`. Compare the downloaded bytes and the asset digest to the locally generated checksum before making the release stable/latest. The updater checks GitHub's HTTPS release metadata for the uploaded asset's exact name, size and SHA-256 digest. The build prints the verified digest instead of keeping a checksum file. For manual verification, run `Get-FileHash -Algorithm SHA256` on the installer. If the asset or digest is unavailable, the app offers the official release page but cannot run setup.
5. Verify discovery, download, cancellation, installation and first launch from the preceding update-capable build. Version 1.5.79 predates the updater and needs one manual installation. Setup is interactive: before launching it the player saves its normal state on close. Cancelling setup leaves the old version in place. Reopening the old app does not report a successful upgrade.

**Runtime and data:** Uninstall removes managed program files. It leaves downloaded audio libraries and user-created playlists/settings alone. Fresh installations download the missing audio libraries from Un4seen on first launch. No executable signing key is required or used by the local build script; a SHA-256 digest is an integrity check, not an Authenticode signature.
